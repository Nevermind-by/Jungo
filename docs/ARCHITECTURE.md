# Архитектура Jungo

## Принятые решения

- Платформа: macOS 26 Tahoe и новее.
- UI: SwiftUI; AppKit используется для системных диалогов, активации окна и глобальной горячей клавиши через Carbon Event Manager.
- Хранилище: SwiftData; пользователь может выбрать локальную папку для активной базы через Settings scene.
- Режим: local-first, без аккаунта, backend и синхронизации.
- Сборка: Swift Package Manager executable target и скрипты упаковки .app.
- Иконка создаётся локальным Swift-скриптом и iconutil; внешний binary asset не нужен.
- JSON-импорт добавляет новые доски, а не заменяет текущие данные.

## Слои

### Presentation
RootView управляет выбранной доской, фильтрами по приоритету/метке/просрочке, корзиной, диалогами и действиями пользователя. TaskCardView показывает карточку и метки. Карточка обёрнута в Button, чтобы быть доступной для клавиатуры и VoiceOver. Цвет метки по умолчанию детерминированно вычисляется по её тексту; пользовательские переопределения хранятся в AppStorage как JSON-словарь, ключи нормализуются в нижний регистр. TaskEditorSheet редактирует содержимое, сроки, метки и чек-лист; для описания есть режим Markdown-просмотра. QuickAddTaskSheet создаёт задачу по короткой форме, не открывая полный редактор.

### Domain
JungoCore содержит чистые функции TaskOrdering, TaskLabels и ArchiveValidation. Проверка версии JSON-архива, уникальности ID, ссылок и непустых названий не зависит от SwiftUI и SwiftData и покрывается unit-тестами.

### Persistence
SwiftData ModelContainer и ModelContext обеспечивают локальное сохранение. `VaultStore` создаёт контейнер до открытия главного окна: при первом запуске сохраняется стандартная конфигурация SwiftData, а при наличии security-scoped bookmark открывается `Jungo.store` в выбранной папке. Если сохранённая папка недоступна, приложение показывает экран ошибки и не переключается молча на пустую базу. Перенос сохраняет исходный контекст, создаёт отдельный контейнер в целевой папке, копирует все четыре модели с исходными UUID и проверяет количества/идентификаторы и связи перед активацией bookmark. Уже существующий целевой `Jungo.store` не перезаписывается. После проверки приложение просит завершить и запустить его заново, чтобы новый контейнер открыл целевую базу. JSON-экспорт остаётся отдельным способом резервного копирования. Для основного контекста включён isUndoEnabled, поэтому сохранённые изменения доступны через системный Undo/Redo. Во время импорта архивов используется отдельный ModelContext без UndoManager: импорт не вмешивается в незавершённые изменения основного UI-контекста. При ошибке вставки или сохранения выполняется rollback изолированного контекста; основной UI-контекст не откатывается. При ошибке сохранения обычной операции основной контекст откатывает незаписанные изменения, чтобы они не попали в базу при следующем сохранении. Ошибки чтения существующих досок пробрасываются, а не подменяются значением по умолчанию. Успешный импорт сохраняется одним вызовом save(). Для основного контекста Undo/Redo остаётся системной историей SwiftData, а не отдельной историей для каждого поля.

Модели Board, BoardColumn и TaskCard используют UUID и целочисленный sortOrder. Board.isArchived отделяет архивные доски от активных; архивирование не удаляет колонки, задачи или чек-листы. TaskChecklistItem ссылается на задачу через taskID. Срок задачи необязательный, метки хранятся строкой и нормализуются при отображении. TaskCard.isInTrash позволяет восстанавливать задачу до окончательного удаления.

### Archive
JungoArchiveDocument из JungoCore задаёт Codable JSON-формат версии 1; SwiftData-операции вынесены в app-расширение. Статус архива доски, метки, срок, корзина и пункты чек-листа опциональны при декодировании, поэтому старые архивы читаются без этих полей. Декодирование старого формата покрыто unit-тестом. Перед импортом проверяются версия формата, уникальность ID, ссылки между сущностями и непустые названия. Импорт создаёт новые UUID и новые доски, сохраняет существующие данные и выполняется через изолированный контекст. После успешного импорта метод возвращает ID последней добавленной доски, поэтому интерфейс выбирает импортированную доску без зависимости от момента обновления @Query.

### Packaging and CI
Scripts/build-app.sh собирает release executable, генерирует AppIcon.icns, создаёт bundle metadata и подписывает локальную сборку ad-hoc. Версия CFBundleShortVersionString и CFBundleVersion задаются через JUNGO_VERSION и JUNGO_BUILD_NUMBER с проверкой формата; package-release включает версию в имя ZIP. Scripts/package-release.sh выполняет Developer ID signing, notarization и staple при наличии настроенных учётных данных. GitHub Actions workflow на macOS 26 запускает unit-тесты, собирает bundle и проверяет plist/иконку.

## Основные сценарии

- Перетаскивание карточки на другую карточку вставляет её перед целью; drop на область колонки перемещает в конец.
- Фильтр по метке доступен в меню доски; поиск также проверяет текст меток.
- Дублирование доски создаёт новые ID для доски, колонок, задач и пунктов чек-листа; копирует структуру, метки, приоритеты и сроки, исключает задачи из корзины и сбрасывает отметки чек-листа.
- Дублирование задачи создаёт новый ID, копирует описание, приоритет, срок и метки, вставляет копию сразу после оригинала и копирует чек-лист со сброшенным состоянием выполнения.
- Удаление задачи отправляет её в корзину; восстановление возвращает в исходную колонку. Окончательное удаление из корзины удаляет и пункты чек-листа.
- Удаление колонки переносит задачи в первую оставшуюся колонку; последнюю колонку удалить нельзя.
- Архивирование доски скрывает её из активного списка, сохраняя всё содержимое; восстановление возвращает её в активные доски. Заголовок секции архива показывает число архивных досок.
- Пустые состояния различают отсутствие задач и отсутствие совпадений по фильтру; пользователю предлагается создать задачу или сбросить условия.
- Удаление доски требует подтверждения и удаляет связанные задачи и пункты чек-листа.
- Импорт архива добавляет копии данных, а не заменяет или синхронизирует их. Он использует отдельный контекст; ошибка импорта откатывает только импортируемые изменения.
- Выбранная доска и пользовательские фильтры хранятся локально через AppStorage; они не являются частью файла SwiftData Vault.
- Настройка Vault меняет расположение базы SwiftData, а не только путь экспорта. Пользовательские настройки интерфейса в UserDefaults остаются в текущем профиле macOS.
- Быстрое добавление доступно из меню-баре, по глобальной Cmd+Option+Space и по Cmd+Option+N внутри приложения; обычный Cmd+N остаётся командой новой задачи с открытием полного редактора.
- Глобальная клавиша регистрируется через Carbon Event Manager без сторонних зависимостей и разрешения Accessibility. Если окно закрыто, приложение повторно открывает главное окно и показывает быструю форму.
- Undo/Redo работает на уровне сохранённых изменений SwiftData; это системная история модели, а не отдельная история для каждого поля.

## Проверки

    swift test
    swift run Jungo
    Scripts/build-app.sh
    Scripts/run-app.sh

Unit-тесты покрывают порядок и разбор меток. UI, SwiftData schema migration, генерация иконки и bundle требуют проверки на macOS 26+.

## Ограничения

- Нет облака, совместной работы и аккаунтов.
- Notarized-релиз требует действующих Developer ID и notarytool credentials.
- Перед выпуском нужно проверить VoiceOver, клавиатурную навигацию, большие архивы, восстановление после аварийного завершения и миграцию Vault на реальном macOS 26.
