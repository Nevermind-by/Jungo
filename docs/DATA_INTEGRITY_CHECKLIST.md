# Проверка целостности данных Jungo

Этот документ — ручной acceptance checklist для сценариев, которые не подтверждаются текущим GitHub Actions. Пункты намеренно оставлены неотмеченными, пока соответствующий сценарий не выполнен на реальном приложении и хранилище.

## Статус

- Unit-тесты JungoCore покрывают JSON codec, валидацию архива, совместимость старого формата и построение import plan.
- CI выполняет `swift test` и сборку development app bundle на macOS 26.
- CI не подтверждает транзакционность живого SwiftData store, перенос Vault, миграции, Undo/Redo в интерактивном приложении и восстановление после аварийного завершения.
- Экспериментальные SwiftData integration tests удалены после падения SwiftPM test runner с `signal 5`; это ограничение покрытия задокументировано.

## Vault

### Перенос хранилища
- [ ] Перенести непустую базу в пустую папку.
- [ ] Сверить количество досок, колонок, задач и пунктов чек-листа до и после переноса.
- [ ] Сверить связи: колонка → доска, задача → колонка, пункт чек-листа → задача.
- [ ] Проверить архивные доски, корзину, метки, приоритеты, сроки и чек-листы.
- [ ] Убедиться, что исходная база остаётся доступной до успешной проверки новой.
- [ ] Повторить перенос в папку с существующим Jungo.store и SQLite sidecar-файлами.
- [ ] Проверить ошибку записи: исходное хранилище должно остаться активным.

### Восстановление доступа
- [ ] Выбрать папку с корректным Jungo.store; доступ восстанавливается после проверки базы.
- [ ] Выбрать папку без Jungo.store; bookmark/path не меняются.
- [ ] Выбрать пустой, посторонний или повреждённый файл Jungo.store; он не становится активным хранилищем.
- [ ] Проверить базу с нарушенными ссылками; bookmark не сохраняется.
- [ ] Отключить внешний диск, перезапустить приложение и убедиться, что Jungo не переключается молча на пустую базу.
- [ ] Подключить диск снова и повторно восстановить доступ.

## Импорт и экспорт
- [ ] Экспортировать доску со всеми типами данных; проверить JSON и ожидаемые записи.
- [ ] Импортировать архив в непустую базу; существующие записи не перезаписываются.
- [ ] Импортировать один архив дважды; обе копии независимы и получают новые ID.
- [ ] Сверить связи импортированных колонок, задач и пунктов чек-листа.
- [ ] Проверить неизвестный priorityRawValue, archive status, due date, labels, trash и checklist state.
- [ ] Импортировать архив старого формата без необязательных полей.
- [ ] Импортировать архив с неверной версией, пустыми названиями, дублирующимися ID, повреждёнными ссылками и некорректным JSON; частичных записей быть не должно.
- [ ] Убедиться, что ошибка импорта не откатывает несохранённые изменения основного UI-контекста.
- [ ] Экспортировать поверх существующего файла и проверить полную замену.

## Undo / Redo
- [ ] Изменить заголовок и описание задачи; Undo/Redo восстанавливают значения.
- [ ] Изменить приоритет, срок и метки; Undo/Redo восстанавливают состояние.
- [ ] Переместить задачу между колонками; Undo/Redo восстанавливают колонку и позицию.
- [ ] Изменить порядок задач; Undo/Redo восстанавливают порядок.
- [ ] Переместить задачу в корзину и восстановить её.
- [ ] Проверить несколько последовательных изменений и последовательность Undo/Redo.
- [ ] После Undo/Redo проверить связи checklist items.
- [ ] Проверить, что Undo/Redo не меняют другую доску.

### Необратимые операции
- [ ] Удалить доску; проверить каскадное удаление связанных записей.
- [ ] Удалить колонку; убедиться, что задачи перенесены в первую оставшуюся колонку.
- [ ] Удалить задачу навсегда из корзины; её checklist items также удаляются.
- [ ] Повторно открыть приложение и проверить сохранность результата.

## Перезапуск и восстановление
- [ ] Создать и изменить данные, штатно закрыть приложение, открыть снова и сверить данные.
- [ ] Повторить с выбранным внешним Vault.
- [ ] Проверить повторный запуск после принудительного завершения приложения после успешного сохранения.
- [ ] Убедиться, что недоступность выбранного Vault не приводит к созданию пустой базы по умолчанию.

## Автоматическое покрытие
- JungoCore: JSON codec, archive validation, обратная совместимость и import-plan tests.
- GitHub Actions: `swift test`, development app bundle, Info.plist, executable и AppIcon.
- Не покрыто автоматикой: интерактивные SwiftData операции, миграции, перенос Vault, системный Undo/Redo и аварийное восстановление.

## Как фиксировать результат

Для каждого прогона записать версию macOS, commit приложения, сценарии Pass/Fail, шаги воспроизведения и приложить логи/скриншоты ошибок. Отмечать checkbox только после фактического выполнения.
