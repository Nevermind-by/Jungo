# Разработка и Git workflow

## Требования

- macOS 26 Tahoe или новее.
- Xcode Command Line Tools и Swift 6 toolchain.
- Интернет нужен только для GitHub; основные сценарии приложения локальные.

## Локальные команды

    swift test
    swift run Jungo

## Правило веток

Каждый функциональный блок — отдельная ветка. Именование: feature/<short-name>, fix/<short-name>, docs/<short-name>.

## Цикл работы

1. Проверить актуальный main.
2. Сформулировать критерии готовности и риски.
3. Создать feature-ветку.
4. Реализовать законченный блок вместе с тестами и документацией.
5. Запустить доступные проверки и просмотреть diff.
6. Исправить найденные проблемы.
7. Создать один содержательный коммит или небольшой набор связанных коммитов.
8. Открыть PR с описанием изменений, тестов и известных ограничений.
9. После проверки выполнить merge в main.

## Чек-лист ручной проверки

- [ ] Создание и переименование доски.
- [ ] Создание, редактирование и удаление задачи.
- [ ] Перетаскивание в другую колонку.
- [ ] Перестановка внутри колонки.
- [ ] Перестановка колонок и проверка сохранённого порядка.
- [ ] Удаление колонки с переносом задач.
- [ ] Удаление доски с подтверждением.
- [ ] Поиск и фильтры не меняют данные.
- [ ] Экспорт JSON и повторный импорт как копии.
- [ ] Повреждённый JSON вызывает понятную ошибку.
- [ ] Закрытие и повторный запуск сохраняют изменения.
- [ ] Проверка в светлой и тёмной теме.

## Принцип

Не отмечать проверку выполненной, если команда или сценарий фактически не запускались. Если среда не предоставляет macOS/Swift, зафиксировать это в PR и оставить точные команды для последующей проверки на Mac.
