# Дорожная карта Jungo

Дорожная карта описывает результат этапа, а не жёсткие календарные обещания. Каждый функциональный блок реализуется в отдельной feature-ветке и попадает в `main` после проверки.

## Этап 0 — Основа проекта
- [x] Создать репозиторий и базовую документацию.
- [x] Зафиксировать продуктовые принципы и границы MVP.
- [ ] Уточнить ключевые продуктовые решения.
- [ ] Выбрать минимальную поддерживаемую версию macOS.
- [ ] Зафиксировать правила ветвления, тестирования и релизов.

**Готово, когда:** любой участник понимает цель продукта, ближайший результат и способ внести изменение.

## Этап 1 — Каркас приложения
- [ ] SwiftUI-приложение с корректной структурой проекта.
- [ ] Навигация: боковая панель и рабочая область.
- [ ] Дизайн-токены, типографика, отступы, состояния hover/focus.
- [ ] Светлая/тёмная/системная темы.
- [ ] Базовые accessibility-метки и клавиатурная навигация.
- [ ] Демонстрационные данные только для разработки.

**Готово, когда:** приложение запускается на выбранной версии macOS, компилируется и имеет согласованный каркас интерфейса.

## Этап 2 — Локальная модель данных
- [ ] Модели Board, Column, Task, Label и ChecklistItem.
- [ ] Локальное хранение с версионированием схемы.
- [ ] Репозиторий данных отделён от UI.
- [ ] Сохранение порядка досок, колонок и карточек.
- [ ] Миграции, ошибки хранения и тесты целостности.
- [ ] Экспорт/резервное копирование — минимум формат и контракт определены до релиза.

**Готово, когда:** данные переживают перезапуск, а операции над моделью тестируются без запуска UI.

## Этап 3 — Полезный Kanban
- [ ] CRUD досок и колонок.
- [ ] CRUD карточек и подробная форма редактирования.
- [ ] Drag-and-drop между колонками и внутри колонки.
- [ ] Приоритеты, сроки, метки и чек-листы.
- [ ] Пустые состояния, подтверждение удаления и восстановление после ошибок.
- [ ] Тесты порядка и переходов состояния.

**Готово, когда:** можно вести реальную работу на локальной доске без обходных путей.

## Этап 4 — Быстрота повседневной работы
- [ ] Быстрое создание задачи.
- [ ] Поиск и фильтры.
- [ ] Горячие клавиши и меню команд.
- [ ] Сохранение последнего контекста.
- [ ] Производительность при большом количестве карточек.
- [ ] Полировка анимаций, фокуса и поведения окна.

## Этап 5 — Надёжность и выпуск
- [ ] Экспорт и восстановление резервной копии.
- [ ] Проверка поведения при ошибках записи и миграции.
- [ ] Проверка VoiceOver, клавиатуры и масштабирования интерфейса.
- [ ] Регрессионный чек-лист.
- [ ] Подготовка иконки, версии, release notes и упаковки приложения.
- [ ] Проверка установки и обновления на чистом профиле.

## После MVP — только по результатам использования
- Вид календаря или timeline.
- Шаблоны досок.
- Меню-бар и quick capture.
- Синхронизация и совместная работа.
- Импорт из других менеджеров.
- Интеграции и AI-функции.

## Приоритет ближайшего блока

После согласования открытых решений начать с **Этапа 1: каркас приложения**. Не добавлять зависимости и сложную инфраструктуру до появления проверенного сценария, который их требует.
