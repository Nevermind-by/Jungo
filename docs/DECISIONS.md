# Решения и открытые вопросы

Документ фиксирует решения, которые влияют на продукт и реализацию. Предположения не считаются окончательными, пока не подтверждены.

## Принятые стартовые принципы

| Решение | Статус | Причина |
|---|---|---|
| Нативное приложение macOS | Предварительно принято | SwiftUI с точечным использованием AppKit даёт системное поведение |
| Local-first, без обязательного аккаунта | Принято для MVP | Минимум трения, работает офлайн, нет серверной стоимости |
| Сначала личный Kanban | Принято для MVP | Быстрее проверить основную ценность |
| Новая функция в отдельной ветке | Принято | Изолированное ревью и понятная история |
| Крупные законченные блоки, не частые мелкие пуши | Принято | Меньше шума и более осмысленные изменения |
| Документация в репозитории | Принято | План, решения и инструкции живут рядом с кодом |

## Требует решения до начала реализации

### 1. Минимальная версия macOS
**Предложение:** выбирать поддерживаемую версию по доступным API и установленной системе разработки, не поднимать минимум без практической причины.

Влияет на: SwiftUI API, SwiftData, упаковку приложения и тестирование.

### 2. Локальное хранилище
**Кандидаты:** SwiftData или SQLite.

Критерии выбора: миграции, предсказуемость сортировки, экспорт/импорт, тестируемость, минимальная версия macOS. Решить после проверки моделей и сценариев восстановления.

### 3. Первая платформа распространения
**Кандидаты:** локальная сборка для собственного использования; позже — подписанное и нотарифицированное приложение вне Mac App Store либо публикация в Mac App Store.

Для первого этапа не блокирует разработку.

### 4. Название и визуальная идентичность
Jungo — рабочее название репозитория и продукта. Иконка, акцентный цвет и финальная дизайн-система должны быть отдельным согласованным блоком, а не случайным набором украшений.

## Шаблон записи решения

Для значимых решений добавлять:
- **Контекст:** какая проблема возникла.
- **Решение:** что выбрано.
- **Альтернативы:** что рассматривали.
- **Последствия:** преимущества, ограничения и стоимость изменения.
- **Статус:** предложено / принято / заменено.

## Не делать без отдельного решения

- Не добавлять обязательную регистрацию.
- Не вводить облачный backend в локальный MVP.
- Не подключать аналитику или отправку пользовательских данных.
- Не добавлять тяжёлые сторонние зависимости без обоснования.
- Не заявлять поддержку функций, которых ещё нет.
