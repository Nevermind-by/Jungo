# Решения и открытые вопросы

## Принятые решения

| Решение | Статус | Причина |
|---|---|---|
| Нативное приложение macOS | Принято | SwiftUI и точечный AppKit |
| Минимальная версия macOS 26 Tahoe | Принято | Можно использовать актуальные API без поддержки старых систем |
| Локальное хранилище SwiftData | Принято | Системное решение Apple для моделей и persistence |
| Только локально, без синхронизации | Принято | MVP без аккаунтов, backend и сетевых зависимостей |
| Нативный стиль macOS | Принято | Системная типографика, навигация, контекстные меню и appearance |
| Личный Kanban сначала | Принято | Сначала проверяем основной пользовательский сценарий |
| Новая функция — отдельная ветка | Принято | Изолированный diff и ревью |
| Крупные законченные блоки | Принято | Не создавать шум из мелких коммитов |
| Документация в репозитории | Принято | Решения и план рядом с исходным кодом |

## Решения по реализации

- Первый каркас использует Swift Package Manager с executable target, чтобы держать сборку и unit-тесты в одном простом пакете.
- Для первого запуска создаются демонстрационная доска, три колонки и несколько карточек.
- Хранение использует SwiftData без включения CloudKit.
- Перед распространением приложения нужно отдельно добавить полноценную упаковку .app, подпись/нотаризацию либо подготовку для Mac App Store.

## Открытые вопросы

1. Нужно ли поддерживать несколько окон или достаточно одного главного окна?
2. Нужны ли архив и корзина, или удаление задачи сразу окончательное?
3. Нужны ли метки и сроки уже в первом функциональном релизе?
4. Какой способ импорта/экспорта нужен: JSON, CSV или оба?
5. Следует ли делать меню-бар/quick capture сразу после базового Kanban или отложить до стабилизации?
