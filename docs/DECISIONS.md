## Решения реализации

- Модели Board, BoardColumn, TaskCard и TaskChecklistItem используют UUID.
- После перемещения карточек и колонок порядок нормализуется от нуля.
- Чек-лист хранит заголовок, состояние выполнения, порядок и taskID.
- Удаление задачи переносит её в корзину, не удаляя запись и checklist items.
- Архивирование доски меняет только isArchived; её колонки, задачи и чек-листы сохраняются. Старые JSON-архивы без поля isArchived импортируются как активные доски.
- Импорт создаёт новые UUID для всех сущностей и добавляет доски после уже существующих.
- Хранение не подключает CloudKit и не отправляет данные по сети.
- Настройки Vault меняют путь основного SwiftData store. Пользовательские UI-настройки в AppStorage/UserDefaults остаются отдельно.
- При переносе создаётся новый store, модели копируются с сохранением UUID, а запись bookmark активируется только после проверки целевой базы. Файл источника не удаляется автоматически.

## Уточнение scope — 2026-10-30

- Jungo предназначен прежде всего для личного использования на одном Mac.
- Основное хранилище — локальная SwiftData; облачная синхронизация и аккаунты не планируются.
- GitHub используется для исходного кода и по желанию для публикации готовых сборок.
- Mac App Store, коммерческая дистрибуция и сложная инфраструктура обновлений не являются целями текущего проекта.
- Developer ID и notarization нужны только если пользователь решит распространять готовое приложение за пределами собственного Mac; это не блокирует личное использование.


## Визуальная система — 2026-10-30

- Основной визуальный ориентир — нативный Liquid Glass в macOS: эффект используется на интерактивных контролах, например поиске и действии добавления колонки; системные sidebar и toolbar сохраняют нативное поведение.
- Колонки и карточки относятся к слою контента, поэтому используют системные материалы и тонкие границы, а не Liquid Glass. Так сохраняются иерархия, читаемость и умеренная глубина.
- Срочные и просроченные задачи получают дополнительный маркер, но важность не передаётся одним цветом: текстовые метаданные и accessibility labels сохраняются.
- Рабочая область использует мягкие акцентные подсветки, основанные на системном цвете, без фиксированной светлой/тёмной палитры. Системная тема и контраст остаются под контролем macOS.
- Системные меню, панели инструментов, диалоги и стандартные контролы сохраняются нативными. Не имитировать будущие API macOS 27: использовать публичные SwiftUI/AppKit API доступной целевой версии и перепроверять визуально на актуальной системе.
- Визуальная проверка в светлой/тёмной теме, при увеличенном масштабе интерфейса и с клавиатурной навигацией остаётся обязательным финальным ручным этапом.
