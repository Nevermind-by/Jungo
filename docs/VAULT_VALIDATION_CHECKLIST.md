# Чек-лист проверки локального хранилища Vault

Этот чек-лист относится к настройке расположения SwiftData-хранилища из PR «Добавить настраиваемое локальное хранилище Vault». Выполнять на macOS 26+ на копии пользовательских данных. Не использовать единственную рабочую базу для негативных сценариев.

## Подготовка
- [ ] Экспортировать JSON-резервную копию и сохранить копию исходного файла `Jungo.store` вместе с доступными SQLite sidecar-файлами после полного завершения приложения.
- [ ] Зафиксировать исходное расположение базы и количество сущностей: доски, колонки, задачи, пункты чек-листов.
- [ ] Подготовить данные разных типов: активная и архивная доски, задачи в обычных колонках и корзине, сроки, метки, разные приоритеты, заполненные и незаполненные чек-листы.
- [ ] Убедиться, что в тестовой целевой папке отсутствует `Jungo.store`.

## Открытие существующего хранилища
- [ ] Обновить/запустить сборку с существующим хранилищем, созданным предыдущей версией Jungo.
- [ ] Проверить, что доски, порядок колонок и задач, архив, корзина, метки, сроки и чек-листы доступны без повторного импорта.
- [ ] Изменить задачу, закрыть приложение штатно и открыть повторно; изменение должно сохраниться.
- [ ] Проверить меню «Правка → Отменить/Повторить» после сохранённого изменения.

## Успешный перенос
- [ ] Перенести Vault в новую локальную папку через «Настройки → Хранилище».
- [ ] Убедиться, что перед переносом показано подтверждение и указано, что приложение потребуется перезапустить.
- [ ] После успешной проверки новая папка должна содержать `Jungo.store`; приложение должно предложить завершить работу.
- [ ] Повторно открыть Jungo и проверить все данные из раздела «Подготовка».
- [ ] Сравнить количество сущностей до и после переноса; идентификаторы и связи должны сохраниться, дубликаты не должны появиться.
- [ ] Проверить, что исходная база осталась на прежнем месте и не была удалена.
- [ ] Создать и изменить задачу в новом Vault, перезапустить приложение и убедиться, что изменения сохраняются уже в новом расположении.
- [ ] Проверить «Открыть в Finder»: открывается папка активного хранилища, а не прежняя папка.

## Негативные сценарии и восстановление
- [ ] Выбрать папку, в которой уже есть `Jungo.store`: перенос должен остановиться с понятной ошибкой; существующий целевой файл и исходная база не должны измениться.
- [ ] Выбрать папку, где отсутствует `Jungo.store`, но остался один из SQLite sidecar-файлов (`Jungo.store-wal`, `Jungo.store-shm` или `Jungo.store-journal`): перенос должен остановиться, а существующий sidecar-файл не должен быть удалён.
- [ ] Отменить диалог подтверждения: перенос не должен начаться, настройки хранилища не должны измениться.
- [ ] Выбрать недоступную/удалённую папку или отключить внешний диск после настройки Vault, затем запустить приложение: должно появиться сообщение об ошибке, а не пустая новая база.
- [ ] При недоступном выбранном Vault проверить, что экран ошибки показывает сохранённый путь, чтобы пользователь мог понять, какой диск/каталог нужно восстановить.
- [ ] Восстановить подключение диска и перезапустить приложение: исходные данные должны снова открыться.
- [ ] В сценарии восстановления доступа выбрать папку без `Jungo.store`: приложение должно отказаться переключать хранилище.
- [ ] Восстановить доступ к папке с существующим `Jungo.store`, перезапустить приложение и проверить прежние данные.
- [ ] Проверить выбор папки с пробелами и нелатинскими символами в пути.
- [ ] Если доступно, проверить папку на внешнем диске и перезапуск приложения после извлечения/повторного подключения диска.
- [ ] После смены выбранной папки проверить, что доступ к предыдущему security-scoped URL освобождён, а новый доступ устанавливается; после повторного запуска должен открываться только выбранный Vault.
- [ ] Если доступ к целевой папке временно не был получен, восстановить доступ и повторить запуск: приложение должно повторно запросить security scope, а не считать старый URL активным.

## UI, доступность и регрессия
- [ ] Проверить перенос с большим количеством задач и чек-листов; интерфейс должен оставаться отзывчивым, ошибки должны отображаться понятно.
- [ ] Проверить клавиатурную навигацию и VoiceOver в настройках хранилища, диалогах подтверждения и ошибках.
- [ ] Убедиться, что сохранённые фильтры и цвета меток остаются на месте после переноса. Они хранятся в настройках приложения, а не в файле Vault.
- [ ] После переноса проверить создание, редактирование, дублирование, перемещение, архивирование и удаление задач/досок, импорт/экспорт JSON и Undo/Redo.
- [ ] Проверить JSON round-trip задачи с неизвестным `priorityRawValue`: после импорта и повторного экспорта исходное значение должно сохраниться, даже если интерфейс отображает fallback-приоритет.

## Результат
Записать версию macOS, версию/build Jungo, сценарии Pass/Fail, шаги воспроизведения дефектов и приложить логи/скриншоты ошибок. Не считать перенос проверенным только по наличию файла: обязательны повторный запуск приложения и сверка данных.
